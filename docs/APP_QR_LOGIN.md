# Вход в приложение Dogma по QR

Сценарий: пользователь уже авторизован на сайте, открывает «Войти по QR», а
приложение на телефоне сканирует код. Сайт показывает устройство и просит
подтвердить вход. Только после подтверждения приложение получает токен.

## Почему не «просто сканирование»

QR-код — это одноразовый секрет. Если его сфотографировать, вход всё равно не
произойдёт, пока пользователь на сайте не нажмёт «Подтвердить вход». Сайт при
этом показывает имя устройства, которое отсканировало код.

## Схема

```
Сайт (cookie-сессия)                 Backend                    Приложение
        │                               │                          │
        │ POST /auth/qr/start           │                          │
        │──────────────────────────────►│                          │
        │ { id, code, qrPayload }       │                          │
        │◄──────────────────────────────│                          │
        │                               │  POST /auth/app/qr/scan  │
        │                               │◄─────────────────────────│
        │                               │  { code, deviceName }    │
        │                               │─────────────────────────►│
        │ GET /auth/qr/:id (poll)       │                          │
        │──────────────────────────────►│  status = scanned        │
        │◄──────────────────────────────│                          │
        │ POST /auth/qr/:id/confirm     │                          │
        │──────────────────────────────►│  status = confirmed      │
        │                               │  GET /auth/app/qr/status │
        │                               │◄─────────────────────────│
        │                               │─────────────────────────►│
        │                               │  POST /auth/app/qr/claim │
        │                               │◄─────────────────────────│
        │                               │  { token }               │
        │                               │─────────────────────────►│
        │ GET /auth/qr/:id (poll)       │                          │
        │──────────────────────────────►│  status = approved       │
```

## API для приложения

### 1. Сканирование

`POST /auth/app/qr/scan`

```json
{
  "code": "<код из QR>",
  "deviceName": "Pixel 8",
  "platform": "android",
  "appVersion": "1.0.0"
}
```

Ответ `200`:

```json
{
  "id": "…",
  "status": "scanned",
  "user": { "name": "Иван Иванов", "email": "i.ivanov@dogma.ru" },
  "deviceName": "Pixel 8",
  "platform": "android",
  "expiresAt": "2026-11-04T12:03:00.000Z"
}
```

Ошибки: `404 INVALID_CODE`, `410 EXPIRED`, `409 ALREADY_SCANNED`
(QR уже сканировало другое устройство), `409 ALREADY_CONFIRMED`,
`409 ALREADY_USED`.

### 2. Ожидание подтверждения

`GET /auth/app/qr/status?code=<код>`

Возвращает тот же объект сессии. Приложение опрашивает его раз в 1–2 секунды,
пока `status` не станет `confirmed` (можно забирать токен), `expired` или
`cancelled`.

### 3. Получение токена

`POST /auth/app/qr/claim`

```json
{ "code": "<код из QR>" }
```

Ответ `200`:

```json
{
  "token": "<Bearer-токен>",
  "tokenType": "Bearer",
  "expiresAt": "2027-02-02T12:00:00.000Z",
  "user": { "name": "Иван Иванов", "email": "i.ivanov@dogma.ru", "kind": "user" }
}
```

Токен показывается один раз. Дальше приложение передаёт его в заголовке:

```
Authorization: Bearer <token>
```

Работают те же эндпоинты, что и на сайте: `/auth/me`,
`/api/v1/vpn/subscription`, `/api/v1/vpn/routing`, `/api/v1/chat` и т.д.
Выход: `POST /auth/app/logout` с Bearer-токеном.

## Формат QR

По умолчанию QR содержит deep-link:

```
dogma://login?code=<code>
```

Шаблон задаётся переменной `APP_LOGIN_DEEPLINK` (подстановка `{code}`).
Приложение должно разбирать этот адрес и передавать `code` в API выше.
Если удобнее universal link, задайте, например:

```
APP_LOGIN_DEEPLINK=https://vpn.example.com/app-login?code={code}
```

Тогда на этот адрес нужен обработчик, который открывает приложение.

## Настройки backend

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_QR_TTL_SECONDS` | `180` | Время жизни QR (минимум 30 секунд) |
| `APP_TOKEN_TTL_DAYS` | `90` | Срок действия токена устройства |
| `APP_LOGIN_DEEPLINK` | `dogma://login?code={code}` | Что кодируется в QR |

Миграция:

```bash
psql "$DATABASE_URL" -f backend/migrations/004_app_auth.sql
```

## Безопасность

- В БД хранятся только SHA-256 хэши кода QR и токена.
- Код одноразовый, живёт 3 минуты, после подтверждения и выдачи токена
  повторно не используется.
- Первое сканирование «закрепляет» QR за устройством; второе получает
  `ALREADY_SCANNED`.
- Вход в приложение невозможно без подтверждения на сайте.
- При блокировке пользователя его токены отзываются при следующем запросе.
- Все события (`started`, `scanned`, `confirmed`, `login`, `logout`) пишутся
  в аудит без секретов.
